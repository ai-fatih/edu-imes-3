# 4.1 Проверка функциональности

## Цель тестирования

Проверить, что все функциональные требования (F1–F4) работают корректно, и приложение готово к демонстрации.

## Окружение тестирования

| Параметр | Значение |
|----------|----------|
| Браузеры | Chrome 125, Firefox 127, Safari 17 |
| Устройства | Десктоп (1920×1080), планшет (iPad Air 820×1180), мобильный (iPhone 14 390×844) |
| ОС | Windows 11, macOS Sonoma |
| Сеть | Локальный dev-сервер Vite + production на Vercel |

## Сценарии тестирования

### T1: Загрузка лендинга

1. Открыть `/`
2. **Ожидание:** Hero-блок с градиентом, кнопки «Заказать» и «Наши услуги»
3. Скролл вниз
4. **Ожидание:** плавные анимации при появлении секций

### T2: Навигация

1. Нажать «Наши услуги» в Hero
2. **Ожидание:** плавный скролл к секции Services
3. Нажать «Услуги» в Navbar → скролл к Services
4. Нажать «О нас» → скролл к About
5. Нажать «Контакты» → скролл к Contact

### T3: Форма заказа

1. Нажать «Заказать мероприятие»
2. **Ожидание:** модальное окно с формой, крестик в углу
3. Выбрать тип мероприятия кликом по чипсу
4. Выбрать количество гостей слайдером
5. Заполнить имя и телефон
6. Нажать «Отправить заявку»
7. **Ожидание:** shimmer-анимация на кнопке, текст «✓ Отправлено!», модалка закрывается

### T4: Вход клиента

1. Перейти на `/login`
2. Выбрать вкладку «Клиент»
3. Ввести имя и email
4. Нажать «Войти как клиент»
5. **Ожидание:** редирект на `/dashboard?name=...&email=...`

### T5: Личный кабинет клиента

1. Войти как «Иван Петров» (ivan@example.com)
2. **Ожидание:** приветствие, 3 заказа (свадьба, ДР, мастер-класс)
3. Развернуть заказ «Свадьба»
4. **Ожидание:** комментарии сотрудника видны

### T6: Вход сотрудника

1. Перейти на `/login`
2. Выбрать вкладку «Сотрудник ПБС»
3. Ввести имя
4. Нажать «Войти как сотрудник»
5. **Ожидание:** редирект на `/employee/dashboard?name=...`

### T7: CRM-панель

1. Войти как сотрудник
2. **Ожидание:** 4 стат-карточки (новые, в работе, выполнено)
3. **Ожидание:** таблица всех 5 заказов
4. Нажать на строку заказа
5. **Ожидание:** сайдбар с деталями

### T8: Управление заказом

1. В CRM открыть заказ
2. Изменить статус на «В работе»
3. **Ожидание:** системный комментарий добавлен
4. Написать комментарий сотрудника
5. Нажать Enter (или кнопку ➤)
6. **Ожидание:** комментарий появился

### T9: Сквозной сценарий

1. Клиент создаёт заказ → статус «Новая»
2. Сотрудник видит заказ в CRM → меняет статус → пишет комментарий
3. Клиент заходит в ЛК → видит новый статус и комментарий

### T10: Адаптивность

1. Открыть на мобильном (390px)
2. **Ожидание:** Navbar → гамбургер, Hero → текст адаптирован
3. Карточки услуг → в 1 колонку
4. Форма заказа → поля друг под другом

### T11: 404

1. Перейти на `/ne-suschestvuet`
2. **Ожидание:** страница 404 с иконкой, текстом и кнопкой «На главную»
