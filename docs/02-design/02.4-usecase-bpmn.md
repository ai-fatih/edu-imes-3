# 2.4 Use-case и BPMN диаграммы

## Use-Case диаграмма

### Акторы

| Актор | Описание |
|-------|----------|
| **Клиент** | Пользователь, желающий заказать мероприятие |
| **Сотрудник ПБС** | Менеджер компании, работающий с заявками |
| **Система** | Автоматические действия приложения (генерация ID, системные комментарии) |

## Основные сценарии (User Stories)

### US-01: Оформление заказа

```
Как клиент
Я хочу оставить заявку на мероприятие
Чтобы мне перезвонили и обсудили детали

Критерии приёмки:
- Форма содержит поля: имя, телефон, email, тип, дата, гости, пожелания
- Тип мероприятия выбирается визуальными кнопками
- Количество гостей регулируется слайдером
- После отправки — анимация успеха
- Заказ появляется в ЛК клиента и CRM сотрудника
```

### US-02: Отслеживание заказа

```
Как клиент
Я хочу видеть статус моего заказа и комментарии сотрудника
Чтобы понимать, на какой стадии находится подготовка

Критерии приёмки:
- В ЛК отображаются только мои заказы (фильтрация по email)
- Каждый заказ можно развернуть для просмотра деталей
- Видна история статусов и комментарии сотрудника
```

### US-03: Управление заказами (CRM)

```
Как сотрудник ПБС
Я хочу видеть все заказы, менять их статусы и писать комментарии
Чтобы клиенты получали актуальную информацию

Критерии приёмки:
- Таблица всех заказов с фильтрацией по статусу
- При клике на заказ открывается сайдбар с деталями
- Можно изменить статус через выпадающий список
- Можно добавить комментарий (Enter или кнопка)
- Система автоматически добавляет комментарий при смене статуса
```

## BPMN-диаграмма основного процесса

```
┌──────────┐    ┌──────────┐    ┌───────────┐    ┌──────────┐    ┌───────────┐
│  Клиент   │    │  Система  │   │ Сотрудник │    │  Система  │    │  Клиент    │
│  заполняет│───>│ создаёт   │───>│ меняет    │───>│ обновляет │───>│ видит      │
│  форму    │    │ заказ     │    │ статус    │    │ статус    │    │ изменения  │
└──────────┘    └──────────┘    └───────────┘    └──────────┘    └───────────┘
                                                                    │
      ┌───────────┐    ┌───────────┐    ┌───────────┐              │
      │  Клиент    │<───│  Система   │<───│ Сотрудник │<────────────┘
      │  читает    │    │ сохраняет  │    │ пишет     │
      │  коммента  │    │ комментарий│    │ коммента  │
      └───────────┘    └───────────┘    └───────────┘
```

### Описание шагов процесса

| Шаг | Участник | Действие | Результат |
|-----|----------|----------|-----------|
| 1 | Клиент | Заполняет форму заказа на лендинге | Создан заказ со статусом `new` |
| 2 | Система | Автоматически (system-комментарий) | `Статус изменён на "Новая"` |
| 3 | Сотрудник | Открывает CRM, видит новый заказ | Обзор всех заявок |
| 4 | Сотрудник | Меняет статус на `confirmed` | Система добавляет комментарий |
| 5 | Сотрудник | Пишет комментарий с деталями | `Подтверждено. Площадка: ...` |
| 6 | Система | Сохраняет изменения в localStorage | Данные обновлены |
| 7 | Клиент | Заходит в ЛК, видит обновления | Прозрачность процесса |
| 8 | Цикл | Повторяется до `completed` | Завершение |
